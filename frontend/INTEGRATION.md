# 首批前端联调记录

日期：2026-10-18。后端基线：`1ad51f2`。分支：`feature/web-console`。

环境：Windows、Node.js 24.18.0、项目 Python 3.13 虚拟环境、已安装的 Chrome。依赖固定在 `package-lock.json`。

## 已验证

`npm run build`：TypeScript 检查和 Vite 生产构建通过。

`npm run test:e2e`：真实浏览器 → Vite 同源代理 → FastAPI → 独立 SQLite，未拦截或 mock 业务响应。

| 场景 | 结果 |
| --- | --- |
| 错误令牌、正确管理员令牌、空项目 | 拒绝错误令牌；正确登录显示真实空状态 |
| 页面创建两个任务并设置依赖、验收、执行者、分支、契约 | 后台保存两项任务和真实关联，生成通知 |
| 编辑目标并提交修改理由 | 携带任务版本，成功后重新加载真实数据 |
| 页面刷新 | 任务、修改与选中的详情保持可见；数据来自后端 |
| 模拟另一会话先更新，再提交旧表单 | 返回真实 409，保留本地草稿；明确重读后才能按新版本提交 |
| 构造循环依赖 | 返回真实 422，页面显示错误，数据库依赖未改变 |
| 搜索与状态筛选 | 无匹配时展示明确空状态，可清除筛选 |
| 任务端确认通知后刷新页面 | 展示已确认理解；任务仍是待开始，没有混淆两种状态 |
| 后端进程重启，复用相同数据库，再刷新页面 | 两个任务及修改结果仍在 |
| 审核者登录 | 可以查看；不显示创建/编辑控件 |
| 退出登录再刷新 | 会话令牌清除，回到登录页 |
| 浏览器运行时 | 无未捕获页面异常 |
| 桌面 1440px、手机 390px | 截图检查完成；手机无横向溢出 |
| 手机表单、键盘操作 | 打开后聚焦名称；拒绝全空格名称；Escape 经确认后关闭草稿 |
| 后端暂时离线 | 展示错误和“显示上次数据”，保留已加载任务；恢复后可重新读取 |

## 遇到的问题与处理

- 原始目录有其他会话未提交的后端更改：在独立 worktree 联调，未 stash、提交、覆盖这些改动。
- 工作目录起初没有前端实现：新增前端模块，不改共享契约或后端文件。
- 开发阶段 API 与页面端口不同：由 Vite 代理 `/api`，无需开放后台跨域。
- 网络请求失败不能判断写入是否发生：页面不自动重试创建/编辑，保留信息并提示先刷新确认，避免重复操作。
- 原生弹窗的初始焦点在开发模式下不稳定：在弹窗实际打开后显式聚焦名称输入框，复测通过。
- 生产静态文件需要部署方配置 `/api` 代理，Vite 的代理只在 dev/preview 进程中生效。

本批没有发现阻塞任务列表、详情、创建、编辑的后端接口问题。
最终多人跨机器连接同一个后台、MCP 客户端流程、尚未实现的页面功能不在本次验证范围内。
