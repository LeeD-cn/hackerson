# 人工演示与验收

新电脑按根目录 [README](../README.md) 安装并启动。演示使用一份固定数据库和对应管理员令牌。
第一次启动没有任务是正常情况，Git 不包含运行中的数据库。

## 一、网页 AI 规划

1. 管理员登录，打开“AI 任务规划”。
2. 输入：“两个人、两小时，用 FastAPI、React、SQLite 开发活动签到功能。只拆签到接口和签到页面，页面依赖接口。给出简短验收标准和交接提示词。”
3. 只点一次发送。页面显示等待状态，模板模型等待上限为 180 秒；旧的本地 settings.json 不会自动更新，请按需修改 timeout_seconds。
4. 草案出现后，检查目标、依赖和交接提示词；正式任务列表此时不应增加。
5. 继续对话：“保留两项任务，在接口验收中增加不能重复签到。”检查草案版本递增。
6. 修改一项任务名称，点击“保存草案”；刷新后从“规划记录”选回草案，修改仍在。
7. 点击“确认创建任务”，在确认窗口中再次确认。任务空间应出现对应任务，关系与交接提示词正确。
8. 刷新后任务仍在。若项目进度在生成后被其他成员修改，409 要求重新规划是正常的并发保护。

失败时保留页面错误码和操作顺序。504 表示模型等待超时，不等于所有服务都断开；不要重复点击产生并行请求。
本流程会把项目及任务上下文发给本地配置的外部模型。使用虚构需求和独立数据库可以避免把真实项目内容用于演示。

## 二、跨电脑 Codex MCP

1. 主机启动监听 Wi-Fi 网卡地址的后端。队友浏览器先访问 /health，检查返回 status=ok。
2. 主机管理员创建或选择任务，通过 issue_task_token 签发任务令牌，私下给对应成员，不发送管理员令牌。
3. 队友按 [MCP README](../mcp_bridge/README.md) 配置 stdio，使用本机 Python 和 server.py 路径；后端地址指向主机，不是队友的 127.0.0.1。
4. 重载 MCP，只调用 get_my_context，确认任务 ID 和名称。
5. 再读取最新 context.version，调用一次 update_my_context，在 next_steps 追加一句明确的测试进度，其他字段不传。
6. 重读确认内容一致、上下文版本加 1。网页主机刷新同一任务，在“工作上下文”检查该句与版本。
7. 有第二个任务时，可调用 query_module 检查公开契约；它不返回目标私有工作记录，也不代表模型回答了所有问题。

任务令牌绑定任务，不绑定某次聊天；正式代码仍由成员通过 Git 同步。
“工作记录写了已完成”不会自动改变任务状态；当前 MCP 尚未暴露 report_status。
