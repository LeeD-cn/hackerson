# 三人分工与最小交付

## 共同目标

先证明：创建自由任务 → 两个独立执行者取各自上下文 → 只查询必要接口 → 提出变更 → 人工批准 → 受影响任务确认并完成调整 → 新会话恢复工作。

MVP 单个后台实例管理一个项目。不提前做多租户、远程操纵 Codex、向量库、自主调度或自动重构。

## A：后端与数据（你）

负责 `backend/`；维护 `contracts/`，协调契约变更和主分支集成。

- SQLite 初始化、任务 CRUD、任务依赖与子任务关系。
- 管理员／协调者／审核者／任务身份鉴权，令牌与任务绑定。
- 当前上下文、历史版本、进度，阻止旧版本覆盖新内容。
- 公开契约查询、消息记录、提案、人工审批、依赖影响通知。
- 为 B、C 提供统一 HTTP 服务与稳定错误格式。

验收：重启后数据仍在；任务 A 无法读写任务 B 的私有上下文；过期写入返回 409；一次批准原子更新正式数据并创建通知。

## B：MCP 与接入（队友一）

负责 `mcp_bridge/`，以及本模块的验证脚本／测试。

- 将共享 HTTP 操作包装为 MCP 工具，使用官方 SDK。
- 从环境变量读取后端地址和任务令牌；不把角色/任务身份作为可随意传入的参数。
- 整理每位成员的 Codex 配置示例和连通性诊断。
- 检查两套 MCP 客户端连接同一后端，以及更换会话恢复上下文。

验收：真实 MCP 客户端发现并调用工具；数据库路径不出现在客户端配置中；两个任务看不到对方私有信息；错误保留可操作的原因。

## C：控制台与页面联调（队友二）

负责 `frontend/`，以及本模块的验证脚本／测试。

- 项目与任务列表、任务依赖图或树、任务编辑。
- 上下文摘要、状态、消息、提案和人工审批。
- 展示每次变更影响的任务，以及各任务的通知处理状态。
- 与 A 进行页面联调；整合最终演示路径。

验收：页面操作调用真实 API，刷新仍保留数据；任务字段不写死；提案与正式决策分开展示；通知送达、理解、修改完成分别显示。

## 文件责任边界

| 文件/目录 | 主要维护人 | 其他人怎么协作 |
| --- | --- | --- |
| `contracts/`、共享文档、根依赖 | A 协调 | B/C 提出具体字段变更，由 A 合入后同步 |
| `backend/` | A | 提报复现步骤和接口问题 |
| `mcp_bridge/` | B | 使用公开 MCP 工具，避免复制权限逻辑 |
| `frontend/` | C | 使用共享接口，避免复制业务状态机 |
| `docs/` | 各自补充对应说明 | 同一文件先协调，避免同时大改 |

合并人建议由 A 担任，属于团队建议；Git 本地分支本身不会强制代码审核。

## 开发顺序

实际剩余时间尚未提供，以下是相对顺序，不是承诺的截止时间。

| 阶段 | A | B | C | 阶段出口 |
| --- | --- | --- | --- | --- |
| 准备（本轮） | 数据与契约、Git 基线 | 阅读工具参数与身份规则 | 阅读任务和通知结构 | 三人从同一提交开始 |
| 第一段 | 任务、权限、上下文读写 | 用样例完成 SDK 工具骨架 | 用样例完成任务页面 | 尽早连通上下文读写 |
| 第二段 | 查询、消息、审批和通知 | 两种身份的真实 MCP 流程 | 接真实 API 和审批页面 | P0 闭环运行 |
| 最后一段 | 权限、版本、持久化验证 | 新会话恢复、错误处理 | 页面验证、演示脚本 | 三人一起走完整演示 |

建议预留剩余时间的最后 20% 用于联调。P0 打通后再做 Git 提交审核记录；自动执行合并和模型辅助规划不阻塞 P0。

## 两条协作规则

1. 出现接口分歧，先修改共享契约并通知另外两人，再修改实现。不要用聊天里的临时字段覆盖仓库内的契约。
2. 每次交付说明完成内容、验证命令、尚未实现部分；不把样例、执行者自报测试和真实验证混为一谈。
